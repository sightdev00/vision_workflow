## 工作流设计总目标

当前工作流按照三级演进目标建设：

```text
P-001真实设计与验证实例
→ 算法工程可复用工作流
→ 与具体领域解耦的通用公开库
```

### 第一阶段：P-001设计

- 以RV1126B（历史别名RV1126BP）和HiSilicon DMS统一与重构作为高复杂度真实实例；
- 验证人工经验、工程证据、设计结论、人工决定、实现、外部验证和知识晋升能否形成闭环；
- 持续标记P-001专用内容、算法工程通用内容和潜在领域无关内容；
- 不因形成工作流原型而降低P-001源码、兼容、构建和板端验证要求。

### 第二阶段：算法工程可复用工作流

- 从P-001提取跨平台算法代码审计、统一、重构、迁移和验证的可复用节点及制品契约；
- 将人的领域经验、平台经验、历史经验、兼容经验、重构经验和验证经验作为一等输入；
- 支持按实例裁剪节点和制品，不绑定DMS、芯片、源码路径或固定会话编号；
- 至少在第二个独立算法问题中复用，验证模板无需复制P-001特例即可运行。

### 第三阶段：通用公开库

- 将工作流引擎、模式、领域模板和项目实例分层；
- 提供版本化模式、结构定义、初始化、校验、升级、扩展接口、测试、示例和公开文档；
- 核心引擎不依赖算法工程语义，算法工作流作为可安装或可选择的领域模板；
- 只有在算法模板跨实例复用成立后，才启动通用公开库的独立仓库和发布治理。

阶段晋升不是自动状态转换。每次晋升都必须记录复用证据、未泛化内容、兼容风险和人工决定。

## 管理规则

- 不预先创建未来 Session 文件。
- planned 只表示当前预测，不表示不可调整。
- 工作流节点与Session不是一一对应关系；一个节点可以有多个Session执行尝试。
- 节点状态、依赖、人工门禁和执行尝试以`WORKFLOW.json`为准。
- 每次启动前细化当前 Session 的 Objective 和结束条件。
- 已关闭的 Session 不重新编号。
- 如果一个 Session 超出合理上下文，应关闭当前 Session并新增下一编号。
- 如果某项不再需要，将其标记为 skipped，不删除历史记录。
- 每次关闭前更新本计划中的状态、实际产物和下一 Session。
- SESSION-PLAN.md 的修改进入该 Session 的功能或文档提交。
- tools/problem-session close 仍然只提交当前 Session Handoff。
